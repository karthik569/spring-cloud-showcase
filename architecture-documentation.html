⚡ Sequence Flows & Inter-Service Communication

1. Happy Path Order Placement Flow

The client issues an order creation request. The API Gateway routes the call to order-service, which communicates synchronously with inventory-service via OpenFeign to verify stock before confirming.

sequenceDiagram autonumber actor Client as 🌐 Client participant GW as 🚀 API Gateway (:8080) participant Eureka as 🔍 Eureka Server (:8761) participant Order as 🛒 Order Service (:8081) participant Inv as 📦 Inventory Service (:8082) Client->>GW: POST /api/orders {skuCode: "IPHONE15", quantity: 2} GW->>Eureka: Lookup instance for 'ORDER-SERVICE' Eureka-->>GW: Return Order Service address GW->>Order: Forward POST /api/orders Order->>Eureka: Resolve 'INVENTORY-SERVICE' via LoadBalancer Eureka-->>Order: Return Inventory Service address Order->>Inv: GET /api/inventory/IPHONE15 (via OpenFeign) Inv-->>Order: Return InventoryResponse {inStock: true, quantity: 25} Order->>Order: Apply centralized discount & compute total Order-->>GW: 201 Created {orderId: "ORD-XXX", status: "CONFIRMED"} GW-->>Client: 201 Created JSON response

2. Circuit Breaker Fallback Execution

When inventory-service is slow, down, or fails, Resilience4j intercepts the Feign exception and triggers the declarative fallback without propagating errors to the caller.

sequenceDiagram autonumber actor Client as 🌐 Client participant GW as 🚀 API Gateway (:8080) participant Order as 🛒 Order Service (:8081) participant Inv as 📦 Inventory Service (:8082) participant Fallback as 🛡 InventoryFallback Client->>GW: POST /api/orders {skuCode: "IPHONE15", quantity: 2} GW->>Order: Forward POST /api/orders Order->>Inv: GET /api/inventory/IPHONE15 Note over Inv: Service Unavailable or Timeout (>= 2s) Inv--xOrder: Connection Refused / 500 Error / Timeout Order->>Fallback: Trigger Feign Fallback checkStock("IPHONE15") Fallback-->>Order: InventoryResponse {inStock: false, warehouse: "FALLBACK_CACHE"} Order-->>GW: 400 Bad Request {status: "REJECTED_OUT_OF_STOCK"} GW-->>Client: Graceful rejection message

📦 Microservices Breakdown

Config Server Port 8888

Centralized configuration authority. Supplies runtime configurations for order discounts and inventory warehouse zones from native classpath configuration repository.

  • Active Profile: native
  • Repository path: classpath:/config-repo
  • Endpoints: /order-service/default, /inventory-service/default

Eureka Server Port 8761

Netflix Eureka service registry enabling autonomous client discovery, heartbeat health reporting, and zero-hardcoded-IP communication across instances.

  • Dashboard: http://localhost:8761
  • Heartbeat interval: 30s
  • Prefer-IP: true

API Gateway Port 8080

Reactive Netty reverse proxy with dynamic route resolution (lb://), global logging filters, circuit breaker fallbacks, and aggregated Swagger UI.

  • Framework: Spring Cloud Gateway (WebFlux)
  • Route 1: /api/orders/** → lb://ORDER-SERVICE
  • Route 2: /api/inventory/** → lb://INVENTORY-SERVICE
  • Swagger UI: /swagger-ui.html

Order Service Port 8081

Business microservice managing order transactions. Employs OpenFeign declarative HTTP client, Spring Cloud LoadBalancer, and Resilience4j circuit breakers.

  • OpenFeign: InventoryClient with InventoryFallback
  • Dynamic Config: @RefreshScope for live discounts
  • Swagger UI: /swagger-ui.html

Inventory Service Port 8082

Warehouse and product stock ledger. Features real-time stock allocation checks and artificial failure simulation endpoints for testing circuit breaker scenarios.

  • Stock Store: In-memory concurrent database
  • Simulation: /api/inventory/slow/{sku} and /fail/{sku}
  • Swagger UI: /swagger-ui.html

🛡 Resilience & Circuit Breaker Architecture

Resilience4j monitors call health between microservices. If failures exceed the configured threshold, the circuit transitions into an OPEN state, intercepting further network traffic immediately.

stateDiagram-v2 [*] --> CLOSED: Initial Healthy State CLOSED --> OPEN: Failure Rate >= 50% (Window: 5 calls) OPEN --> HALF_OPEN: Wait Duration expires (5s) HALF_OPEN --> CLOSED: Permitted calls succeed HALF_OPEN --> OPEN: Any failure during trial

Configured Parameters:

  • sliding-window-size: 5 calls
  • minimum-number-of-calls: 3 calls
  • failure-rate-threshold: 50%
  • wait-duration-in-open-state: 5 seconds
  • timelimiter.timeout-duration: 2 seconds
